# Troubleshooting

| Symptom | Check |
|---------|--------|
| **Windows blocked zip extract** or **“Windows protected your PC”** on `devkit4.0-agent-skills.zip` | Expected for **unsigned zips with `.ps1`** from Downloads/email/USB. **Unblock** the zip (Properties → Unblock), or `Unblock-File` then **`Expand-Archive`**. Avoid Extract All from Explorer if SmartScreen blocks it. See [README zip handoff](../README.md#zip-handoff-test-machines). |
| **PowerShell blocked** `configure-*.ps1` / `invoke-*.ps1` after unzip | **Mark of the Web** on extracted scripts. Run once: `Get-ChildItem .\agent-skills -Recurse -Filter *.ps1 \| Unblock-File`, or `powershell -ExecutionPolicy Bypass -File .\scripts\windows\...`. Install skill only unblocks Dev Kit **`WingetGUI_Installer`**, not **`agent-skills`**. |
| **I2-cli-invoke** / `Setup_1.ps1 install exit 1` | Open the skill JSON: **`setup_output_tail`**, **`setup_failure_hint`**, **`install_log_tail`**, and **`C:\temp\logs\install\install_log.txt`**. Common causes: **execution policy** / **not digitally signed** (child PS: use updated skill with `-ExecutionPolicy Bypass`, or `Unblock-File` on `WingetGUI_Installer\**\*.ps1`), not elevated, missing **`JSON\install\applications.json`**, winget &lt; 1.10.390, or **`Microsoft.WinGet.Client`** not installed. Manual: Admin PS → `cd ...\WingetGUI_Installer` → `powershell -ExecutionPolicy Bypass -File .\Setup_1.ps1 install`. Retry with **`-Silent:$false`** if already unblocked in that session. |
| `devkit_status=absent` | Clone **`training.developer.aipc`**, place **`agent-skills`** at repo root, run **Setup_1** if needed. Optional: **`AIPC_DEVKIT_INSTALL_ROOT`** → clone root. |
| `OVMS_SCRIPT_NOT_FOUND` | Clone must include `Windows_Software_Installation\OVMS\ovms_agentic_setup.ps1`. **Partial fetch:** `scripts\windows\fetch-devkit-ovms-slice.ps1 -InstallRoot <repo-root> -Approve` (git sparse-checkout of `OVMS/` only; inner-source auth required). Optional `-IncludeOvmsRuntime` for `ovms.exe` from OpenVINO Model Server releases. |
| OVMS skip on verify | Start with `invoke-ovms-agentic-setup.ps1 -Approve -Pull` or `-SkipLaunch` if server already on `:8000` |
| Skill **`functional_status=blocked`** + **`error.code`** | **`DISK_INSUFFICIENT`**: free space on `%USERPROFILE%\OVMS` volume. **`PORT_CONFLICT`**: use `-ApproveStopOvms` after user approves (only **ovms.exe** stopped). **`PULL_IN_PROGRESS`**: wait or delete **`%USERPROFILE%\OVMS\.skill-state\pull-state.json`** when no download is running (file absent until first **`-Pull`** with current pack). **`RETRY_PULL_REQUIRES_APPROVAL`**: add `-ApproveRetryPull` for resume/re-pull. **`OVMS_NOT_READY`** (provider skill): run `invoke-ovms-agentic-setup.ps1 -Profile agent` first. **`MODEL_INTENT_MISMATCH`**: wrong model on `:8000`. |
| Empty **`C:\temp\ovms.txt`** or no **`C:\temp\logs\ovms`** | **Not** agent-skills pull lock. Pull state: **`%USERPROFILE%\OVMS\.skill-state\`**. Skill JSON may include **`ovms_pull_state_path`**. OVMS errors: detached **`-NoExit`** PowerShell window running **`ovms_agentic_setup.ps1`**. |
| Hermes still on cloud after configure skill | Expected: use **`local_provider_handoff`** steps (`hermes model`, new chat). **`-Apply`** is not implemented. |
| Second OVMS copy / wrong version | See **Where OVMS is installed** below; use `-SkipLaunch` when Dev Kit OVMS is already installed |
| Python/OpenVINO skip | Dev Kit Python/venv paths; run from Dev Kit environment |
| Model pull fails for 0.8B | Fallback: `qwen3-4b` or `OpenVINO/Qwen3-0.6B-int4-ov` per [DECISIONS.md](planning/DECISIONS.md) |
| **Detached OVMS window opens then closes** | Without **`-NoExit`**, PowerShell exits when **`ovms_agentic_setup.ps1`** fails (ownership, pull, port in use) and the error is easy to miss. Updated skill uses **`powershell -NoExit -File ...`**. **Manual:** `cd ...\Windows_Software_Installation\OVMS` and run the same command from the skill JSON **`logs`** / **`launcher_cwd`**. See [admin-vs-user-runtime.md](admin-vs-user-runtime.md). |
| OVMS **Plugin config is in wrong format** / `CACHE_DIR` JSON with `C:\Users\...` | OVMS embeds **`--cache_dir`** in JSON; **absolute** `C:\Users\...` paths break parsing. **Permanent fix:** updated **`agent-skills`** (junction + **no** `-CacheDir`/`-ModelRepositoryPath` on skill launch). After reboot, run **`repair-ovms-user-data-layout.ps1`** once if `...\OVMS\models` or `.ovcache` are normal folders again. Unset **`AIPC_OVMS_USE_CLONE_PATHS`**. Do not call **`ovms_agentic_setup.ps1`** with `-CacheDir 'C:\Users\...'` or `C:/Users/...`. |
| **OVMS** “directory is not owned by the current user” | **Admin vs user mismatch:** Setup_1/2 or an earlier **elevated** `ovms_agentic_setup.ps1 -Pull` created **`models\`** / **`.ovcache\`** (or **`C:\Intel\OVMS\`**) owned by Administrators; standard-user start cannot write. **Fix:** start OVMS **elevated**, or use **user-scoped** paths — set **`AIPC_OVMS_USER_DATA=1`** and re-run **`invoke-ovms-agentic-setup.ps1`**, or manual **`-ModelRepositoryPath`** / **`-CacheDir`** under **`%USERPROFILE%\OVMS`**. See [admin-vs-user-runtime.md](admin-vs-user-runtime.md). |
| **OVMS skill never returns** (old pack) | **`ovms_agentic_setup.ps1`** starts **`ovms.exe`** in the foreground. Updated skill launches it in a **separate PowerShell window** (`-NoExit` on failure) and waits for **`GET /v3/models`**. Leave that window open while OVMS runs. Manual: start server in one window, then **`invoke-ovms-agentic-setup.ps1 -Approve -SkipLaunch`**. |
| **O4-chat** `(404) Not Found` while O2 lists the model | Often **Windows PowerShell 5.1** sending JSON as **UTF-16** via `Invoke-RestMethod`. Updated skill uses **`Invoke-WebRequest`** + **UTF-8** body (same as Dev Kit README). Confirm manually with the recipe `Invoke-WebRequest` to **`/v3/chat/completions`**. If still 404, read O4 message for **HTTP body snippet** (wrong path vs unknown model). |
| Hermes **404** / **Mediapipe graph definition … not found**; **`/v3/models`** shows a **different** name than `config.yaml` | **Model id mismatch:** Hermes sends `model` in chat JSON. `hermes config set model.default` accepts the quoted catalog id **`OpenVINO/Qwen3.6-35B-A3B-int4-ov`**. The short id `Qwen3.6-35B-A3B` is not accepted. **`base_url`** must be **`http://localhost:8000/v3`**. If the browser lists **25B** but you expect **35B**, OVMS is serving a **different graph** — restart with **`invoke-ovms-agentic-setup.ps1 -Profile agent`** and matching **`-Model`**. Re-run **`configure-hermes-ovms.ps1 -Approve`** after OVMS is up so **`serving_model`** matches. |
| Continue **“No models configured”** | Continue reads **`%USERPROFILE%\.continue\config.yaml`** (not Hermes). Confirm **`-Apply`** ran (**P4** pass). Open **Command Palette → “Continue: Open config.yaml”** and check for top-level **`schema: v1`** and a **`models:`** list. Remove legacy **`config.json`** in the same folder if present. **Output → Continue** may show YAML parse errors. Re-run **`configure-continue-ovms.ps1 -Approve -Apply`** (updated pack writes **UTF-8 without BOM**). Reload VS Code. Workspace **`.continue/config.yaml`** overrides global if empty. |
| **`invoke-openvino-coding-assistant-setup.ps1` seems hung** (OVMS window already shows Qwen3.6 35B on **:8000**) | The orchestrator **waits** on a child **`invoke-ovms-agentic-setup.ps1`** process. Older packs used **`-Profile verify`**, which runs **Hermes tool tests** (`ovms_agentic_setup.ps1 -Test`) and **long chat warm-up** polls—often **many minutes** (or appears stuck on **`-Pull`** health wait up to **15 min**). **Safe now:** OVMS keeps running in its **separate `-NoExit` window**; you can open another shell and run **`configure-continue-ovms.ps1 -Approve -Apply`**, or **`Ctrl+C`** the orchestrator only. **Updated pack:** coding invoke passes **`-Profile agent -SkipChatSmoke`** (O2 **GET /v3/models** only, then Continue merge) for **Qwen3.6 35B** on port **8000**. First compile may still take up to **~3 min** on O2 if the endpoint was not ready yet. |
| **`MODEL_ADVERTISED_MISMATCH`** / O2 or C2 fail | Skills match the **catalog pull id** to **`GET /v3/models`** via regex (D9: **`Qwen3\.6-35B-A3B.*`**, D1: **`Qwen3\.5-0\.8B.*`**) plus stem/leaf fallback. **`OpenVINO/Qwen3.5-0.8B-int4-ov` on the server should pass** for verify/smoke. If you only have 0.8B loaded but run **`configure-hermes-ovms`** without **`-Model`**, the default is the **agent** catalog (35B) — run **`invoke-ovms-agentic-setup.ps1 -Profile agent`** or pass **`-Model 'OpenVINO/Qwen3.5-0.8B-int4-ov'`** for smoke-only Hermes. |
| Hermes says **ready for agent chat** but only **0.8B** on `/v3/models` | **`agent_inference_ready: false`**, **`A1-agentic-inference` fail** or OVMS **`partial`** after `-Profile verify`. Run **`invoke-ovms-agentic-setup.ps1 -Approve -Profile agent`**. Read **`user_message`** / **`next_steps`** only. |
| **O4-chat** `(412) Precondition Failed` but **O3-tool-test** passes | **Timing:** `GET /v3/models` can succeed before chat inference is ready. On **`-Profile verify`**, the skill **polls chat (O3-prep)** up to **2–10 min** before **`ovms_agentic_setup.ps1 -Test`**, then marks **O4 pass** when `-Test` text generation succeeds. If O3-prep fails, O3 may still pass once OVMS catches up; O4 falls back to its own chat retries when O3 fails. |
| **Setup_2 / `-Setup2Only` runs for hours** | **Expected** for full `Setup_2.ps1`: GenAI deps, multiple venvs, **LlamaCpp/Vulkan** pip and CMake builds (often **1-8+ hours**). **Check now:** Task Manager for active **`cmake`**, **`cl`**, **`pip`**, **`msbuild`**, **`python`**; folder **`C:\Intel\openvino_genai`**. Old skill wrapper redirected stdout and could **hide output or stall** native tools—use updated skill (child **window**, no redirect) or **`-Setup2InProcess`** / manual: `powershell -ExecutionPolicy Bypass -File .\Setup_2.ps1`. Meta: **`C:\temp\logs\setup2\invoke-meta.txt`**. If only **V3 verify** is needed and **`C:\Intel\openvino_genai`** already exists, skip re-run. To abort: stop the Setup_2 PowerShell process; partial install may still satisfy V3 if the folder is valid. |
| **D9 agent OVMS** — crash or model load fail | **Current D9:** `OpenVINO/Qwen3.6-35B-A3B-int4-ov` on **GPU** (MoE). Use **OVMS ≥ 2026.3.1** (`python_on`): **`upgrade-ovms-runtime.ps1 -Approve`**. Junction layout; no absolute `-CacheDir`. Confirm with `GET /v3/models`. |
| **Retired D9 `OpenVINO/Qwen3.8-27B-int4-ov`** — `openvino.dll` **`0xC0000005`** | Do not use for MVP; replaced by **Qwen3.6-35B-A3B** after lab failure even on OVMS 2026.3.1. Historical: [OVMS v2026.3.1 known issue](https://github.com/openvinotoolkit/model_server/releases/tag/v2026.3.1) on default 3.8-27B HF export. |

## Where OVMS is installed

Discovery order for **`ovms.exe`** (V4, `Find-OvmsInstallDirectory`): **`AIPC_OVMS_ROOT`** → paths under **`AIPC_DEVKIT_INSTALL_ROOT`** → **`C:\Intel\OVMS`** (and `\ovms`) → `-InstallRoot` / other clone paths → **`%USERPROFILE%\OVMS`**. The kit installs **`ovms.exe`** under **`...\Windows_Software_Installation\OVMS\ovms\`** (not directly under **`OVMS\`**). Set env vars when multiple copies exist.

The skill scripts **do not choose** the OVMS install folder at install time; **`ovms_agentic_setup.ps1`** (Dev Kit installer) does. Our verify logic looks for **`ovms.exe`** in the ordered search above (first match wins for V4):

| Path | Typical role |
|------|----------------|
| `C:\Intel\OVMS\ovms.exe` or `C:\Intel\OVMS\ovms\ovms.exe` | Default Dev Kit / agentic setup target |
| `%USERPROFILE%\OVMS\...` | User-scoped install |
| `{installer clone}\OVMS\...` | In-repo layout when using git clone |

**Models** usually sit beside the OVMS tree: `{parent of ovms folder}\models\OpenVINO\...` (see `Get-OvmsModelCacheRoot` in `_skill-common.ps1`).

After **`invoke-ovms-agentic-setup.ps1`**, read the JSON report:

- **`ovms_installations_before`** / **`ovms_installations_after`** — every `ovms.exe` found, **file version**, and path  
- **`ovms_agentic_script`** — which setup script ran (often under an installer **clone**, not the same folder as an older OVMS)  
- **`warnings`** — lists multiple copies if more than one `ovms.exe` exists  

If Dev Kit already installed OVMS and you only want to run models against the **existing** server, avoid reinstall:

```powershell
.\scripts\windows\invoke-ovms-agentic-setup.ps1 -Approve -SkipLaunch -Profile verify
```

Installer logs: `WingetGUI_Installer` logs under Dev Kit clone (see upstream README).
